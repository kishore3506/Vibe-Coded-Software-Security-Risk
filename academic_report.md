## Abstract

The emerging paradigm of **“vibe coding”**—wherein developers author software primarily through high-level conversational prompts and automated AI code generation assistants (e.g., GitHub Copilot, Cursor, ChatGPT, Claude)—has drastically lowered barriers to rapid prototyping. However, this velocity introduces critical software supply-chain vulnerabilities: large language models regularly output code containing legacy security vulnerabilities, buffer overflows, format string vulnerabilities, and dangerous command executions. Because developers often adopt generated code without rigorous manual code audits or formal static analysis, risky patterns propagate silently into production.

This project designs, evaluates, and demonstrates an end-to-end **Artificial Neural Network (ANN)** multi-layer perceptron architecture for automated potential security risk detection in source code snippets. Trained on a stratified subset of the authentic **Microsoft CodeXGLUE Defect Detection (Devign benchmark)** dataset (6,000 real-world C/C++ functions from QEMU and FFmpeg), the model maps source code into an 85-dimensional feature space combining 35 static lexical, cyclomatic complexity, and security-sensitive pattern indicators with 50 TF-IDF syntactic token n-grams. Benchmarked against four baseline classifiers—Logistic Regression, Random Forest, Support Vector Machine (SVM), and Gradient Boosting—the ANN achieves the **highest Recall (40.44%)** and **highest F1-Score (0.4601)** on the holdout test set. We deploy this model in an interactive, defense-in-depth Streamlit screening application that provides risk probabilities, heuristic rule indicators, and academic security disclaimers without executing submitted code.

## 1. Introduction

### 1.1 Software Security and Modern Vulnerability Landscape
Software vulnerabilities—flaws in program logic, memory management, or input handling—remain one of the most persistent attack vectors in modern computing. According to the Common Vulnerabilities and Exposures (CVE) repository and the National Vulnerability Database (NVD), thousands of new vulnerabilities are documented annually, with memory safety violations (CWE-119, CWE-120, CWE-787) and injection flaws (CWE-78, CWE-89) consistently ranking among the MITRE Top 25 Most Dangerous Software Weaknesses.

### 1.2 The Paradigm Shift of "Vibe Coding"
Over the past two years, the software engineering landscape has experienced a profound shift toward **AI-assisted code generation**, colloquially known in industry and developer culture as **“vibe coding”**. In this paradigm, developers describe application intent in natural language, relying on generative AI to produce functions, API integrations, and entire application modules. While this dramatically accelerates time-to-market, it introduces an asymmetrical security challenge:
1. **Lack of Human Scrutiny:** Developers often lack the deep systems security background needed to spot nuanced vulnerabilities (such as subtle off-by-one buffer bounds or improper pointer lifecycles) in AI-generated snippets.
2. **Reproduction of Insecure Training Corpora:** Generative language models are trained on internet-scale public repositories containing millions of lines of historically vulnerable code, thereby perpetuating deprecated patterns (e.g., `strcpy`, unvalidated `system()` calls).
3. **Plausible yet Broken Code:** Code generated by AI often exhibits clean formatting, sensible variable naming, and syntactical correctness, creating a false sense of security while containing exploitable logic.

### 1.3 Need for Automated Machine Learning Vulnerability Screening
Traditional Static Application Security Testing (SAST) tools rely on hand-crafted abstract syntax tree (AST) rules and taint analysis. While effective, conventional SAST tools suffer from high computational overhead, rigid language-specific parsers, and notoriously high false-positive rates that disrupt rapid development workflows. 

Machine learning—and specifically **Artificial Neural Networks (ANNs)**—offers a complementary, lightweight screening layer. By learning non-linear interactions across syntactic token frequencies, cyclomatic branching structures, and API usage distributions, ANNs can rapidly score the potential security risk of code snippets in pre-commit hooks, IDE sidecars, or pre-deployment pipelines.

## 2. Problem Statement

Given a raw source code snippet $C$ generated by an AI assistant or written by a developer during rapid vibe-coding, the objective is to extract a set of deterministic, leakage-free numerical features $\mathbf{x} \in \mathbb{R}^D$ and estimate the conditional probability:

$$P(Y = 1 \mid \mathbf{x})$$

where $Y \in \{0, 1\}$ represents the ground-truth security status ($0 = \text{Secure/Defect-free}$, $1 = \text{Vulnerable/Security Risk}$). 

The model must provide actionable risk probability estimates without executing user-supplied code, avoid data leakage across experimental splits, and be comprehensively evaluated against established baseline machine learning models using authentic, non-fabricated metrics.

The project utilizes the **Microsoft CodeXGLUE Defect Detection Benchmark**, derived from the **Devign dataset** (*Zhou et al., NeurIPS 2019*). The underlying dataset comprises C/C++ functions harvested from two massive, security-critical open-source software systems:
- **QEMU:** A widely deployed machine emulator and virtualizer.

## 7. Artificial Neural Network (ANN) Architecture

The ANN is structured as a regularized deep multi-layer feedforward network tailored for tabular code representation:

| Layer # | Layer Type | Output Dimension | Activation | Regularization / Normalization | Parameter Count |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **0** | Input Layer | $(N, 85)$ | — | — | 0 |
| **1** | Dense | $(N, 128)$ | ReLU | — | $85 \times 128 + 128 = 11,008$ |
| **2** | Batch Normalization | $(N, 128)$ | — | $\gamma, \beta$ learned scale/shift | 512 |
| **3** | Dropout | $(N, 128)$ | — | Rate $= 0.3$ | 0 |
| **4** | Dense | $(N, 64)$ | ReLU | — | $128 \times 64 + 64 = 8,256$ |
| **5** | Batch Normalization | $(N, 64)$ | — | $\gamma, \beta$ learned scale/shift | 256 |
| **6** | Dropout | $(N, 64)$ | — | Rate $= 0.2$ | 0 |
| **7** | Dense | $(N, 32)$ | ReLU | — | $64 \times 32 + 32 = 2,080$ |
| **8** | Dropout | $(N, 32)$ | — | Rate $= 0.2$ | 0 |
| **9** | Dense (Output) | $(N, 1)$ | Sigmoid | — | $32 \times 1 + 1 = 33$ |

### Mathematical Formulation
1. **Activation Function:** Rectified Linear Unit ($\text{ReLU}(z) = \max(0, z)$) is utilized in hidden layers to ensure non-linear representational capacity while mitigating vanishing gradient problems during backpropagation.
2. **Output Layer:** The final neuron applies the logistic Sigmoid function:
   $$\sigma(z) = \frac{1}{1 + e^{-z}}$$
   mapping the final logit into a continuous probability $[0, 1]$.
3. **Loss Function:** Binary Cross-Entropy (Log Loss):
   $$\mathcal{L}(y, \hat{y}) = - \frac{1}{N} \sum_{i=1}^{N} \left[ y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i) \right]$$
4. **Optimization:** Adam optimizer with adaptive first ($m_t$) and second ($v_t$) moment estimates, initial learning rate $\eta = 0.001$.
5. **Regularization Strategy:**
   - **Dropout ($p=0.3, 0.2$):** Randomly zeroes hidden activations during training, preventing co-adaptation of features.
   - **Batch Normalization:** Normalizes intermediate layer activations to zero mean and unit variance, stabilizing training dynamics.
   - **EarlyStopping:** Monitored validation loss with a patience of 10 epochs. In our training run, training terminated at epoch 17, and optimal weights from epoch 7 were restored.
   - **ReduceLROnPlateau:** Halved the learning rate when validation loss plateaued for 4 consecutive epochs.

## 9. Evaluation Metrics & Rationale

In cybersecurity vulnerability detection, evaluation metrics cannot be considered equally:

1. **Accuracy ($\frac{TP+TN}{TP+TN+FP+FN}$):** Measures overall correctness. However, accuracy alone is notoriously deceptive in security settings: a naive model predicting all samples as "Secure" can show high accuracy while failing to identify critical vulnerabilities.
2. **Precision ($\frac{TP}{TP+FP}$):** The proportion of flagged snippets that are genuinely vulnerable. High precision reduces developer alert fatigue.
3. **Recall / Sensitivity ($\frac{TP}{TP+FN}$):** The proportion of actual vulnerabilities successfully detected. **In cybersecurity, Recall is the most critical metric.** A false negative (missing a vulnerable code snippet) permits exploitable vulnerabilities to slip into production.
4. **F1-Score ($2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$):** The harmonic mean of precision and recall, providing a balanced assessment of detection efficacy.
5. **ROC-AUC:** Area Under the Receiver Operating Characteristic Curve, measuring the classifier's discriminative ability across all possible classification thresholds.

## 12. Security Analysis of Vibe-Coded / AI-Generated Software

The rise of prompt-driven software development introduces distinct threat models:

1. **Hallucinated & Deprecated APIs:** LLMs frequently suggest deprecated functions (e.g., `gets`, `scanf("%s")`) because older codebases heavily populate their training datasets.
2. **Missing Boundary Checks:** AI models optimize for concise, functional snippets, often omitting tedious error handling, null pointer verification, and bounds checks.
3. **Insecure Copy-Paste Propagation:** When developers prompt for a solution, they paste the resulting block directly into large codebases. Vulnerabilities remain unnoticed until exposed in production.
4. **Automated Screening as a Defense Layer:** Integrating an ANN vulnerability classifier directly into the developer workflow (e.g., pre-commit hook or IDE extension) provides an immediate, automated sanity check before code reaches code review.

## 13. System Limitations

1. **Feature Space Granularity:** Static lexical and TF-IDF metrics cannot track runtime pointer aliasing, inter-procedural taint flow, or dynamic memory leaks across multi-file projects.
2. **Language Generalization:** While trained on C/C++ systems software, modern vibe coding encompasses web stacks (JavaScript/TypeScript, Python, Go). Adapting to web vulnerabilities (SQL injection, XSS) requires multilingual training corpora.
3. **Label Noise in Public Benchmarks:** Commit-level vulnerability datasets inherently contain labeling noise due to incomplete patches or commits that bundle both functional improvements and bug fixes.

## 14. Future Enhancements
